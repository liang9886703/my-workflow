# 项目测试与验证

`project` 是模板前缀，实例化时统一替换。实例化时依据仓库现有测试框架映射目录和命令，不把本模板的层级名称机械变成新目录。

本 skill 拥有专用测试资产、fixture、测试入口、增量测试选择和代码改动后的完整验证。生产代码旁的局部小型测试由 `project-code-implement` 随实现维护。

## 被测边界

按调用方式和真实主体选择级别，而不是按文件名或是否使用 mock 判断：

| 级别 | 证明对象 | 约束 |
|---|---|---|
| 局部或单元 | 函数、类或局部协作 | 随生产代码维护，不为测试扩大生产 API |
| 模块或组件 | 单个稳定模块的公共行为 | 只经公共入口调用，不导入内部文件或替换被测主体 |
| 程序或集成 | composition root、多个模块或基础设施适配 | 按生产接线组合，可替换明确的外部边界 |
| 系统或端到端 | 完整进程、服务或网络入口的外部结果 | 必需主体使用生产入口，外部依赖替换必须显式说明 |

项目可以使用不同名称或合并层级，但测试说明必须指出实际被测边界。

## 读取与写入

1. 读取需求、目标实现、相邻测试、当前测试配置和已有命令
2. 只有预期行为依赖稳定契约时才读直接相关 reference
3. 现有测试能直接证明行为时优先复用；不能证明时在匹配层级新增最小资产
4. fixture 跟随使用它的测试边界，保留问题输入事实，并去除凭据、签名、个人数据和机器路径
5. 不通过复制生产装配、导入内部实现或用进程内 fake 替换必需主体来伪造更高级测试

本 skill 可以修改专用测试目录、fixture、harness 和验证入口；修改生产实现转交 `project-code-implement`。测试失败后先分类为产品缺陷、测试缺陷、环境问题或未知，不未经分析直接改生产代码。

## 选择与执行

- 先运行能证明目标行为的最小测试或过滤范围，再运行直接相邻测试
- 增量验证通过后，按变更风险和仓库要求执行格式、静态检查、单元、集成、系统与构建验证
- 高成本、真实付费服务、生产数据、外部消息或会改变共享环境的测试，需要用户当前任务明确授权
- 失败即保留命令、退出码和关键证据；不要用重复重跑掩盖非确定性
- 回归测试应在修复前识别错误行为，并在相同输入和断言下证明修复

## 输出

报告新增或修改的用例及其级别、增量测试、完整验证各步骤、未运行项与原因、真实外部服务是否使用、fixture 来源与脱敏，以及仍未覆盖的行为和风险。
