# 项目长期设计文档

`project` 是模板命名空间。实例化时统一替换 skill 名称和所有 `project-*` 引用，并按真实项目删减不存在的文档类型。

本 skill 只维护长期设计 reference；代码任务中的当前实现约束归 `project-code-implement/references/`，任务进度、排查时间线和测试结果不进入长期文档。

## 文档分层与路由

| 需要回答的问题 | 读取或维护的位置 |
|---|---|
| 项目为什么存在、核心概念与系统边界 | `../../references/concept-design.md` |
| 系统怎样分层、依赖和演化 | `../../references/architecture-design.md` |
| 数据由谁拥有、怎样流动和清理 | `../../references/data-design.md` |
| 对外接口与协议契约 | `../../references/api/` |
| 构建输入、产物和交付链路 | `../../references/build/` |
| 单项能力的稳定职责与对象结构 | `../../references/capability/` |
| 部署单元与运行约束 | `../../references/environment/` |
| 以业务入口分类的数据流和状态变化 | `../../references/workflow/` |

创建或评审单项能力文档时，额外读取 [capability 写法](references/capability.md)。其它类型以对应长期 reference 内的具体写法为准，不在本 skill 重复章节模板。

## 内容 Owner

- 新事实写入拥有它的最窄文档；跨域关系写到能够同时约束各方的共同上层
- 相邻文档只保留名称、必要摘要和相对链接，不复制规则正文
- 长期 reference 记录设计原因、不变量、稳定契约、ownership 和演化边界
- callback、字段映射、局部算法、当前目录内的易变接线归实现 reference
- README 只做人工入口，`AGENTS.md` 只做 agent 路由，skill 只做工作规则

## 写入授权与流程

只有用户明确要求维护长期设计或独立文档任务时，才新增、修改或迁移 `.agents/references/`。普通代码实施即使发现文档缺口，也保持长期 reference 只读并在交付中报告候选变更。

1. 先读目标文档、直接入链、相关代码与配置，分清当前事实、目标设计和未决问题
2. 选择单一 Owner，确认不会与概念、架构、数据、能力或 workflow 文档重复
3. 只写影响长期决策的内容；让可变方案在约束范围内保留发散空间
4. 修改稳定契约时检查上游、下游、API、数据流和环境假设
5. 删除或移动文档时修复所有有效入链，不保留旧路径的影子正文

## 禁止内容

- 不逐函数、逐文件翻译源码，不用长伪代码替代设计
- 不记录一次性命令、原始日志、任务状态、发现时间线或测试结果
- 不把尚未决定的方案写成既定事实；明确区分事实、约束和待决策项
- 不为完整而创建空章节、空文档或没有实际 Owner 的目录

## 验证与交接

检查相对链接、术语、ownership、依赖方向和兼容边界一致。交付时说明正文 Owner、依据的代码事实、同步检查范围，以及仍需实现验证或用户决策的内容。
