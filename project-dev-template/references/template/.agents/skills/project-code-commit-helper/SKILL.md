# 项目提交信息助手

`project` 是模板前缀，实例化时统一替换。本 skill 只分析和写提交信息，不代表代码评审通过，也不执行任何 Git 写操作。

## 分析范围

1. 读取仓库的提交约定与用户指定范围
2. 默认检查工作区状态、暂存区统计、文件状态和完整暂存 diff
3. 暂存区为空时明确说明；只有用户要求时才分析未暂存或指定提交范围
4. 按用户可观察行为、测试、文档、构建和运行时影响归纳变更，而不是罗列文件
5. 独立变更确实需要拆分时说明边界；用户要求单一提交时生成覆盖其指定范围的一条信息

工作区已有改动默认属于用户。不要建议使用 destructive Git 命令清理，也不要把未读或未确认文件纳入描述。

## Conventional Commit

使用仓库已有语言和格式约定；没有额外约定时采用：

```text
<type>(<scope>): <imperative description>
```

- `type` 按主要结果选择 `feat`、`fix`、`test`、`docs`、`refactor`、`perf`、`build`、`ci` 或 `chore`
- `scope` 使用真实稳定边界；无法提供信息时可以省略，不使用 `misc`
- subject 简洁表达主要结果，不堆实现步骤，结尾不加句号
- body 按需说明动机、影响和验证；不兼容变化使用仓库约定的 breaking 标记
- issue 或工单标识仅在用户提供或仓库有可验证约定时加入，不生成默认编号

## 输出

给出与分析范围对应的推荐提交信息及必要的范围说明，明确依据的是暂存区、未暂存区还是指定提交，并声明未执行任何 Git 写操作。
