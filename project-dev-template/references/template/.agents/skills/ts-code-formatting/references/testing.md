# TypeScript 测试

测试框架、目录和入口以目标仓库 instructions、`package.json` 和相邻测试为准

## 事实源

编写单元测试前先读被测行为直接相关的需求、API、流程或局部设计，再读导出声明和相邻测试。预期结果来自行为契约，不从 private helper、内部调用链或当前分支结构反推

## 文件和入口

- 沿用仓库现有测试框架、import、matcher、生命周期和文件布局
- 通过目标文件已有 export 调用被测 class 或函数，只读取完成调用所需的最小生产代码
- 不为测试增加 export、public getter 或生产旁路
- 测试名称表达前置状态、操作和可观察结果

## 用例

断言返回值、错误、边界交互或外部可观察状态，不断言 private 状态、helper 调用次数或非契约分支。多个 expect 可以共同证明一个行为，不按 expect 数量机械拆测试

普通操作通常执行一次公开调用，生命周期、重试、replay 或状态迁移可以执行必要的真实调用序列

## Test double

按需替换网络、文件系统、时钟、外部 client 和相邻依赖，不替换被测能力自身的判断与状态变化。优先使用当前代码已有依赖边界，不为了测试强行扩大生产 API

异步测试必须 await 或返回 Promise，timer、全局状态和进程资源在用例结束时清理，避免依赖真实网络和不受控时间
