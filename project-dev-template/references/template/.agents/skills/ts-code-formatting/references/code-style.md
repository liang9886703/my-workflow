# TypeScript 文件组织

## 文件边界

沿用目标仓库已有公共入口和目录结构，不为了统一形态新增 barrel、factory、`api.ts` 或第二个公共入口

只在单文件使用的类型就近定义。对象具有独立 ownership、生命周期、调用者或可单独验证的职责时再拆文件，不按固定行数机械拆分

## 文件顺序

文件通常按以下顺序组织，局部可读性优先

1. imports
2. 模块常量和就近使用的类型
3. 导出 class 或函数
4. 私有 helper

不定义无 owner 的模块级可变状态，不为了“定义与实现分离”机械创建 `types.ts`

## class 和函数

| 形态 | 适用场景 |
|---|---|
| class | 有实例身份、资源生命周期、可变私有状态或需要实现框架接口 |
| 导出函数 | 无实例 ownership 的操作或明确的函数式公共边界 |
| 私有 helper | 能降低认知复杂度、隔离协议映射或复用真实逻辑 |

不要为了表面模块化拆函数，也不要把多个独立决策塞进一个函数。以职责、测试边界和控制流清晰度判断

class 成员按 constructor、public、protected、private 大致分组；只有真实继承场景才使用 protected。公共可变字段应有明确理由

## 导出和 imports

- 优先跟随仓库现有导出方式，新增公共 API 时倾向命名导出
- 类型导入使用 `import type` 或行内 `type`
- 同一路径的值和类型通常合并为一条 import
- 修改 export 前检查生产、测试、脚本和动态入口引用
- 不为测试或假设的未来复用扩大生产 API

## 日志

在请求边界、状态变化、外部调用、失败和资源生命周期处记录有排障价值的信息。不要为每个 helper 或成功分支机械加日志，也不要输出敏感信息、完整附件或无界内容
