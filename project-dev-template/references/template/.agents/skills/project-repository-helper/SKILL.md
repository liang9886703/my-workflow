# 项目仓库治理

`project` 是模板命名空间。实例化时将目录名、frontmatter 中的 `name`、标题和相互引用统一替换为项目标识；替换前不要把本模板当成某个真实项目的事实来源。

## 负责范围

- 建立或调整仓库级目录边界、子项目入口和 composition root 的位置
- 维护根与子目录 `AGENTS.md` 的适用范围、事实 Owner、读取路由、修改边界和验证要求
- 维护与仓库结构直接相关的跟踪、忽略、工作区和工具入口规则
- 在移动目录或拆分子项目时同步修复有效的相对链接、入口和 ownership 路由

不在本 skill 中编写完整架构设计、业务能力正文、生产实现细节或测试操作手册。对应内容分别交给 `project-docs-helper`、`project-code-implement` 和 `project-test-verification`。

## 读取路由

1. 读取当前作用域的 `AGENTS.md`、仓库清单、构建清单和实际目录树
2. 用版本控制的已跟踪文件确认正式资产，不把缓存、本地安装包或临时生成物当成仓库规范
3. 涉及稳定边界时读取最小相关的概念、架构和数据 reference
4. 涉及某一实现、测试、skill 或交付资产时，再读取对应项目级 skill

README 面向人提供快速入口；`AGENTS.md` 面向 agent 提供约束与路由；长期 reference 拥有设计正文。三者只互相链接，不复制全文。

## 修改约束

- 只有任务明确涉及仓库初始化、结构调整或治理时才修改仓库级文件
- 保留用户已有改动；移动或删除前先解析真实引用方和生成关系
- 新目录必须有清晰 owner、入口和验证方式，不能只为分类创建空层级
- 结构调整不得顺便改变业务语义；确需修改生产行为时转交 `project-code-implement`
- 仓库事实只能有一个正文 Owner，其它入口保留摘要和相对链接

## 验证与交接

- 检查目录、清单、相对链接、发现规则和版本控制状态一致
- 运行仓库已有的非破坏性结构校验；没有入口时明确报告缺口
- 交付时列出调整后的 owner 与路由、未迁移资产以及需要后续设计或实现任务处理的事项
