# TypeScript 审查和重构

## 优先级

1. 运行时错误、数据损坏、竞态和资源泄漏
2. 类型断言、any 或缺失值掩盖的真实边界问题
3. API、失败契约、异步 ownership 和模块边界
4. 重复模型、误导命名和难以验证的职责
5. 纯格式问题

输出具体文件和行号、实际影响与最小修复方向。现有 formatter 能自动处理的内容不作为人工 finding

## 重构

保持用户要求范围内的行为，不混入无关格式整理。优先收紧外部边界和 ownership，再处理内部类型；不要用 `as`、`!`、wrapper 或通用泛型把错误模型压下去

拆文件、函数和类型以独立职责、调用者、生命周期和可验证性为依据，不使用固定行数或参数数量作为门槛

JavaScript 迁移或类型错误修复时，先确定输入输出和运行环境，再逐步增加类型。第三方类型 workaround 收敛到边界，并保留能解释其必要性的证据
