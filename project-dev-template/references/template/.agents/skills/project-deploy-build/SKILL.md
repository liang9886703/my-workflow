# 项目构建与交付

`project` 是模板前缀，实例化时统一替换。实例化时从真实仓库提取构建线、产物和环境名称，不把示例项目的提供商、镜像布局或命令带入新项目。

## 读取路由

- 先读根 `AGENTS.md`、当前 manifest、构建脚本、CI 配置、容器入口和部署清单
- 构建输入、生成顺序、产物与发布链路读取 `../../references/build/`
- 部署单元、网络、共享资源、权限与运行约束读取 `../../references/environment/`
- 改动产品行为或代码域时同时读取 `project-code-implement`
- 验证入口与测试资产读取 `project-test-verification`

## 先区分的边界

- 构建时与运行时：生成、编译、打包不能和启动阶段的配置、迁移、恢复混写
- 产物与环境：同一不可变产物优先通过显式配置适配环境；确需多条构建线时分别说明输入和责任
- 模板与密钥：仓库只保存可审查模板和占位，不写真实凭据、token、签名或私有证书
- 镜像与部署：镜像内容、entrypoint、编排资源和集群策略各有 Owner，变更时检查但不复制正文
- 共享资源与流水线：挂载、网络、缓存或远端存储变化不自动等同于构建步骤变化

## 修改约束

- 只修改用户任务覆盖的构建、打包、CI、配置模板、entrypoint 或部署资产
- 先解析产物消费者和发布顺序，再移动、重命名或删除生成物
- 配置生成必须区分公开默认值、环境覆盖和秘密注入，并定义缺失值的失败语义
- 构建失败应尽早终止并保留可诊断输出；不得用静默降级发布不完整产物
- 实际发布、推送镜像、修改共享环境或执行不可逆迁移前，需要用户明确授权

## 验证与交接

验证构建输入、生成顺序、产物清单、版本标识、配置渲染、启动方式和部署声明一致；按风险运行静态校验、可重复构建、镜像或包检查、启动探测和部署前检查。

交付时说明受影响的构建线、产物、构建时与运行时变化、秘密来源、已执行验证、未执行的真实发布操作，以及回滚或兼容注意事项。
