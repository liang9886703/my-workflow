# Implementation domain reference 写法

本文件是创建或维护 `references/<domain>.md` 时使用的写作指南，不是某个真实代码域的事实文档。实例化后按稳定生产代码域复制或改名，并在上级 `SKILL.md` 建立读取路由。

## 定位

Implementation reference 记录修改当前实现时必须知道、但仅靠局部代码不容易可靠推出的约束。它补充长期 capability 设计，不重新定义业务职责或建立第二套 ownership。

同一 reference 服务一个稳定代码域，不按需求、缺陷、版本或工单创建。只有任务确实改变实现约束、阅读入口或关键边界时才更新。

## 推荐结构

按实际内容选用以下章节；不适用时省略。

1. 开头说明：代码域职责、对应长期 reference、当前状态，以及正文描述当前事实还是受约束的目标结构
2. `文件组织`：公共入口、composition root、关键内部边界和非显然接线；稳定对象树只链接长期文档
3. `接线与执行边界`：输入输出、副作用、必要顺序和结果条件，不逐项转述函数
4. 领域特有约束：协议映射、算法不变量、状态机或框架限制，使用准确标题
5. `关键数据与资源`：影响 ownership、跨调用共享、identity 和清理的数据、port、client、task、timer 或锁
6. `并发与生命周期`：创建、复用、替换、取消、幂等、迟到结果和释放边界
7. `异常与兼容`：局部检测、错误映射、降级、清理和版本兼容
8. `迁移约束`：当前事实、目标结构、过渡边界和阻塞；迁移完成后删除失效内容
9. `测试约束`：必须验证的公开行为、文件级算法和 test double 边界，不写命令
10. `边界`：允许的导入、导出、调用方向及相邻代码域的局部归属

## 关键数据与资源

只记录会改变实现决策的项目。每项说明业务语义、层级、owner、writer、reader、创建时机、共享基数、identity 和清理边界。

- 请求或调用级：随一次入口调用创建和释放，不泄漏到长期对象
- 会话或任务级：跨多个步骤复用，但必须按 identity 隔离并有终止清理
- 进程或应用级：由 composition root 创建，显式注入并随运行时释放
- 文件级无状态能力：只通过参数和返回值协作，不伪装成有生命周期的对象

项目可替换为自己的层级名称，但必须保持 owner、共享和清理语义清楚。不要罗列局部变量或因为存在类型声明就创造稳定对象。

## 测试约束

记录需要保护的可观察结果、真实调用序列、边界输入、失败结果与允许替换的外部依赖。不要指定测试目录、级别或命令，也不要把 private 状态、helper 调用次数和当前分支结构变成稳定契约。

## 禁止内容

- 不复制长期 reference 的目标、职责、总体数据流和稳定对象 ownership
- 不逐 class、函数、代码行或条件分支解释源码，不写等价伪代码
- 不记录任务步骤、排查时间线、原始日志、提交信息、测试结果或一次性命令
- 不把临时 workaround 写成永久原则；需要保留时说明适用条件、退出标准和兼容原因
- 不用 implementation reference 掩盖缺失的长期设计；把候选缺口留在代码交付中报告
